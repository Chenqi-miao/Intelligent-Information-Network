# 数据集驱动的研究工作流

> 从本次项目中总结的可复用工作流。

## 背景

做论文复现类项目时，经常遇到：论文描述 vs 实际数据有偏差、多工具协作困难、数据下载反复失败。
这个 skill 记录了一套经过验证的工作流。

---

## 工作流

```
读论文（Method + Result 反推数据使用方式）
    ↓
获取数据集 URL（选稳定直达的源，Zenodo 优先）
    ↓
下载数据（注意检查文件完整性，md5sum 或预期大小）
    ↓
EDA：直接读 CSV 验证论文描述（不要只看论文猜）
    ↓
按论文复现代码 → 实验 → 分析
```

## 关键原则

### 1. 论文 → 数据 最好反推
论文 Section 的 Method 和 Result 章节通常隐含了数据使用方式。
比如"we trained on 1,831 time series" → 反推出用了三类数据。
直接问论文"数据在哪"往往找不到答案，要倒过来推理。

### 2. 下数据优先选稳定源
- Zenodo（学术数据集首选，直连快）
- GitHub Releases（次选）
- 避免需要梯子的源，AI 对网络问题不敏感，会浪费大量时间在错误排查上
- 下载后立刻检查文件大小是否匹配

### 3. EDA 阶段：读 CSV > 读论文
论文对数据的描述常常是理想化的。
例如论文说"缺失率 ~60%"，实际 CSV 里根本不存在 NaN 值——
缺失是以"行不存在"的形式体现的，必须对比 times.csv 的行数才能算对。

EDA 检查清单（可复用）：
- [ ] 总行数 vs 期望行数（gap 缺失率）
- [ ] 各列基本统计（min/max/mean/std）
- [ ] 时间序列是否有周期性（ACF 图）
- [ ] 不同层级的稀疏度对比
- [ ] 指标间相关性（热力图）
- [ ] 数据分布是否偏斜（是否需要 log 变换）

### 4. 多 Agent 协作
- 不同 AI 有不同能力侧重，分开用但**不要跨 agent 传代码**
- CLAUDE.md 式的规范在不同 agent 间不通用
- 最佳实践：一个 agent 负责完整的一条链路，不要 A 写代码 B 来跑

### 5. 卡住时
- 先去读原始数据（CSV/JSON），别在论文里找答案
- 论文省略的细节（如缺失值处理方式）可以从开源代码里翻
- 如果某个数据集一直下不完整，换个更小的子集开始
